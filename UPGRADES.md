# Upgrades

## 0.2.0 to 1.0.0 — the shared Nexus layer 0.3.0: the exchange layer on every socket, the shared translator and pair launcher, a CLI takes its datom alone

Every member moves to 1.0.0 together: the daemon, the translator, the CLIs and
the wire, emission and core crates. A 1.0.0 daemon and a 0.2.0 translator do
not interoperate: rebuild and restart the pair whole.

**Pins.** `nexus-exchange`, `nexus-querying` and `nexus-serving` 0.3.0 at nexus
a4bc011; `translator-client` and `translator-serving` 0.3.0 at translator
2739d58, with translator 0.5.2 at 29601a3; signal 11.2.0 at 4f5cbb9;
signal-belief-nexus 1.0.0 at c8542d3 and meta-signal-belief-nexus 1.0.0 at
d85f795; build-base cdcd760, which registers both contracts; Ethos generated by
ethos-zero 30.0.1 (2999292).

**The sockets speak the exchange layer.** The Nexus's public and meta sockets
are served by `nexus-serving`: each greets with the digest of its own call
contract (`crates/wire/ethos/public-call.ethos`, `meta-call.ethos`), answers
each exchange once, or a Subscribe with every frame of a `signal::Stream`
(`Opened`, `Changed`, `Lagged`, inside `Subscribed`), and ends every exchange
with `End`, so a refused Subscribe is answered once and ended. The translator
is served by `translator-serving`: each text lane carries the lane header, is
answered with each answer and then `Ended`, or `Failed`. The emission lane
answers `EmissionAnswer` (`Attempted.EmissionAttemptOutcome` or
`LaneFailed.LaneFailure`); a failed lane is answered to the caller as the
effect's own refusal, as before. The daemon's state is owned by one Kameo actor;
a subscription drains its events when one is announced, not on a timer. The
repository polling thread stays the Nexus's own.

**One Nexus bootstrap.** The daemon reads `nexus_serving::NexusBootstrap.{
Place Admission PeerIdentity InstanceId }`, which the shared pair launcher
writes. Its owner is the login of its paired translator, which must be the
effective user, as the old `BootstrapOwner` had to be; its memory is
`belief.memory` in the place's state directory (`MemoryPlacing`), the name the
old deployment gave it, and a sole `belief.sema` is still renamed to it. The
socket paths are named after the Nexus (`SocketPaths`).

**The pair launcher every translator shares.** `belief-pair '<Place>'` is
unchanged for its caller. The package's wrapper runs the shared launcher with
the admission the old deployment named (frame deadline 70000, frame capacity
8388608, retry delay 25) and the text budget `{ 100000 64 }`, and ends both
children on SIGTERM or SIGINT. The deployment's settings are
`crates/translator/deployment.datom`, the same twenty sets in the same order
(`HarnessLayout` and `PlacementDefault` written by the contract's names), and
`belief-translator` takes them as its one argument: at its first start it
applies them through the Nexus's meta socket, conditional from revision 0, then
the Nexus's sockets and its peer, as the old launcher did after start, and stops
at the first revision the Nexus already holds. The meta lane waits until that
is done, so the first Configure of a place is answered at revision 24, as
before. The translator restores its settings from the Nexus at start, trying
the meta socket again for the admission deadline while the Nexus is not yet
answering.

**The translator's settings.** The translator follows each Configured answer
of the Nexus, and takes the Nexus's snapshot when an answer skips a revision,
answering `ConfigureRefused.Unavailable` only when it cannot. Its text budget
starts at the bootstrap's and is the configured `TextBudget` once set. The
emission lane admits only the paired Nexus process (the shared paired peer);
`AllowedNexusPeers` is still a setting the readiness awaits. Ordinary text sent
before the Nexus is configured is answered `Refused.NotReady` by the Nexus
rather than held.

**Removed.** The daemon's own listeners, framing and peer admission; the
translator crate's text client, servers, bootstrap reading, peer observation
and pair launcher, with `Deployment`, `SocketName`, `MemoryFileName`,
`NexusExecutable`, `TranslatorExecutable`, `TextLimits`, `text_request`,
`text_request_stream`, `observe_peer` and `admit_peer`; the wire's
`transport.ethos`; the ignored codex process proof `crates/daemon/tests/e2e.rs`,
whose path the pair test now runs without a provider.

**Every Datom text is the same.** `Resolve.[]`, `Configure.{ None
RepositoryPolling.211 }` and `Configure.{ None OrdinaryPeers.[ { flow { <uid>
<pid> } } ] }` are read and answered as they were; a Subscribe prints its
frames as `Subscribed.Opened.…` and `Subscribed.Changed.…`.

**To adopt (metaflow).** Write `$XDG_CONFIG_HOME/nexus/belief.datom`
(`~/.config/nexus/belief.datom`) holding `{ <place-name> }`, the place
`belief-pair` is started with, whose runtime is `$XDG_RUNTIME_DIR/nexus/<place-name>`.
Drop the place argument from every `belief-nexus` and `belief-nexus-meta` call:
each takes its datom alone. Start the pair with the package's `belief-pair`; the
package's `libexec/belief-pair` is now the shared launcher, which takes the
place, the Nexus, the translator, the admission and the text budget, and
`belief-translator` needs its deployment argument, so neither is started bare.
A stop may signal the launcher alone. Rebuild the daemon, the translator and the
CLIs together.

## 0.1.0 to 0.2.0 -- the first balanced-text 0.33 adoption, and a prepared Place at start

Source only. This revision is not deployed and moves no live state by itself.

**Selected cohort.** signal-belief-nexus 0.3.3 (`1a8b`), meta-signal-belief-nexus 0.4.1 (`341e`),
translator 0.3.2 (`5719`), Signal 10.3.0 (`7afb`), datom-codec 0.33.0 (`eabe`), protos 0.33.0
(`3c7a`) and ethos-zero 19.2.0 (`5a5d`). The stored memory file name and the memory image
encoding are unchanged: `MemoryImage`, its encoding and `FileMemory` load and store are not edited,
and the memory file selection code moves unchanged from the launcher into the daemon crate.

**Startup change.** translator 0.2.0 moved a Place from `metaflow/NAME` to `nexus/NAME` under the
runtime and state roots. A start now prepares the Place before it opens anything:

- A standard place (state at `<root>/nexus/NAME`) moves a sole legacy `<root>/metaflow/NAME`
  intact to `<root>/nexus/NAME` under the translator per-place exclusion, then creates the
  directories. Both present is refused as `StateConflict` and nothing is changed.
- An explicit place only creates directories; it never looks for legacy state and takes no lock.
- The memory file is then selected inside the same scope: a sole `NAME.sema` file is renamed to the
  current file name; both present is a typed conflict naming both paths. A current name that ends
  in `sema` is refused before any effect, because it would be its own legacy name.
- The launcher validates every input (place name, owner, admission, the five names, the sockets
  against the Place runtime) before it prepares the place or starts a child, prepares the place,
  then starts the Nexus and the translator, and writes the contract envelope and the bootstrap.
  The Nexus validates the same bootstrap with the same validator and prepares the same Place, so a
  direct start cannot open a store the launcher would have moved.
- The Nexus binary reads the 8-byte contract envelope first and refuses a bootstrap of another
  contract before it reads the bootstrap.

**Operator guidance.**

- Conflict, both stores present (`StateConflict` or the memory file conflict): nothing was
  changed. Inspect both, keep the one that holds the data you want, move the other aside by hand,
  and start again. Do not delete either before reading it.
- Failed start after a successful move: the destination is intact. Start again; a repeat moves
  nothing and completes.
- A failed selection or preparation reports its cause; the launcher exits and stops its children.
  Every failure after the children start, including a meta call that fails because the Nexus died,
  stops and reaps both children before the launcher exits.
- The exclusion serializes cooperating starts of a standard place only. An explicit place is not
  serialized, and an alias the process cannot observe is outside it.
- The bootstrap owner and the paired translator are checked against the effective user; that is
  consistency, not authentication of whoever writes the pipe.

How to deploy: repin the user environment's belief-nexus input to this revision, build and switch,
after the lock-service and contract owners agree; none of that is done here.
